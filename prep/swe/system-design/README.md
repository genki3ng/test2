# System Design — 大型分布式系统设计 cheatsheet

> 目标：任意大型系统题，5 分钟内拉出骨架、35–45 分钟讲清一个可扩展架构与**取舍**。中高级 SWE 权重最高、最拉分。
> 核心心法：**先想清楚再说、先广后深、主动报权衡**。没有标准答案，考的是工程判断与沟通。配合 [../question-bank.md](../question-bank.md) 的 `sd-*` 抽题。

## 7 步框架（每道题都走，时间先广后深）

1. **需求澄清（功能 + 非功能）**——最值钱的一步
   - 功能：核心用例有哪些？先聚焦 2–3 个，别贪多。
   - 非功能：规模（DAU/QPS）、读写比、延迟要求、可用性 vs 一致性、数据量级。
   - **明确范围**：和面试官对齐「这次重点设计什么」，砍掉枝节。
2. **容量估算**（粗略即可，给数量级）
   - QPS = DAU × 人均操作 / 86400；峰值 ≈ 平均 × 2~10。
   - 存储 = 条数 × 单条字节 × 副本 × 保留期。
   - 带宽 = QPS × 单条大小。读写比决定缓存/从库策略。
3. **API 设计**：列核心接口（REST/RPC），入参出参、关键字段。
4. **数据模型**：核心实体与关系，选 SQL / NoSQL（按访问模式、规模、一致性要求）。
5. **高层组件图**：客户端 → 负载均衡 → 服务 → 缓存 / DB / 队列；画出数据流（读路径 vs 写路径分开讲）。
6. **逐组件深入**：挑 1–2 个核心组件深挖（如发码、Feed 扩散、消息路由），讲算法与数据结构。
7. **扩展与权衡**：识别瓶颈/单点/热点 → 给缓解（缓存、分片、复制、队列、限流）→ 明说取舍。

## 扩展工具箱（按需取用，每个都要会讲「为什么 + 代价」）

- **缓存**：旁路（cache-aside，最常见）/ 读穿 / 写回 / 写穿；问题：失效策略（TTL/LRU）、缓存击穿/穿透/雪崩、一致性（缓存与 DB 不一致窗口）、热点 key。
- **分片 / Sharding**：按 key 哈希 / 按范围 / **一致性哈希**（减少扩容时的数据迁移）；问题：跨分片查询、热点分片、再平衡。
- **复制 Replication**：主从（读写分离，读扩展）/ 多主（写扩展但冲突）/ 无主；权衡：同步复制（强一致、慢）vs 异步（快、可能丢数据/读到旧）。
- **负载均衡**：L4/L7、轮询/最少连接/一致性哈希；健康检查、会话保持。
- **消息队列 / MQ**：削峰、解耦、异步、削平突发（Kafka/RabbitMQ）；权衡：至少一次 vs 精确一次、顺序保证、消费者幂等、积压。
- **限流 Rate Limiting**：令牌桶/漏桶/滑窗；分布式用 Redis 原子计数（详见 `sd-04`）。
- **CDN**：静态/媒体内容就近分发，卸载源站。

## 核心理论速记

- **CAP**：网络分区（P）不可避免，分区发生时只能在 **一致性 C** 与 **可用性 A** 间取舍。多数互联网系统选 **AP + 最终一致**；金融/库存等选 CP。
- **一致性级别**：强一致 / 读己之写 / 单调读 / 最终一致——按业务挑，越强越贵。
- **ACID（事务）vs BASE（最终一致）**：SQL 重 ACID；大规模分布式常退到 BASE。
- **幂等性**：重试/至少一次投递场景必须设计幂等（去重 key / 唯一约束 / 版本号）。
- **读写比驱动设计**：读多写少 → 重缓存 + 读副本；写多 → 分片 + 异步 + 队列。

## SQL vs NoSQL 怎么选

| 选 SQL | 选 NoSQL |
|---|---|
| 强一致、事务、复杂关联查询 | 海量数据、高写入、灵活 schema |
| 数据关系强、规模可控 | 简单访问模式（KV/文档/宽列） |
| 例：交易、账务 | 例：Feed、日志、KV 缓存、时序 |

> 实战常**混用**：核心一致性数据放 SQL，海量/高吞吐放 NoSQL + 缓存。

## 经典题速查（套 7 步框架，记住「核心难点」）

| 题 | 核心难点 | 关键决策 |
|---|---|---|
| **短链 (TinyURL)** | 发码 + 读多 | 发号策略（自增Base62 / 随机 / KGS）+ 重缓存 + CDN（`sd-01`） |
| **Feed 流** | 扩散 + 大 V | 推/拉/**混合** + 收件箱 + 在线排序（`sd-02`） |
| **聊天系统** | 长连接 + 路由 + 顺序 | WebSocket 网关 + 连接映射 + Pub/Sub 路由 + 序列号（`sd-03`） |
| **限流器** | 分布式原子计数 | 令牌桶 + Redis Lua（`sd-04`） |
| **附近的人** | 空间索引 | Geohash / QuadTree / S2 + 邻格补偿（`sd-05`） |

## 常见追问（提前想好）

- 「QPS 翻 10 倍怎么扩？」→ 水平扩 + 缓存 + 分片，指出新瓶颈。
- 「这里挂了会怎样？」→ 单点识别 + 冗余/降级/重试。
- 「数据一致性怎么保证？」→ 一致性级别选择 + 幂等 + 冲突解决。
- 「热点 key / 热点用户怎么办？」→ 多级缓存 / 本地缓存 / 拆分 / 大 V 特殊路径。

## 避坑

- 别一上来画细节——先澄清、先框定范围。
- 别只堆技术名词——每引入一个组件都说「解决什么问题 + 代价」。
- 别忽视非功能需求——它决定整个设计走向。
- 时间管理：留够时间到「扩展与取舍」，那是高级信号最集中的地方。
