## 算法与数据结构

### [ds-01] 两数之和 / 何时该上哈希表
给一个数组和 target，返回和为 target 的两个下标。延伸：为什么哈希表能把 O(n²) 降到 O(n)？
**要点**
- 暴力 O(n²) 双层循环 → 用哈希表「边遍历边查补数 target-x」降到 O(n)/O(n) 空间。
- 关键直觉：**哈希表把「查找/去重/计数」从 O(n) 降到 O(1)**，是减一层循环的最常见手段。
- edge：同一元素不能用两次（先查再存）、重复值、找不到的返回约定。
- 口头先说复杂度与思路，再写；写完主动跑一个例子验证。

### [ds-02] 双指针：有序数组 / 原地操作
何时用双指针？举两类：对撞指针（两数之和 II、盛最多水）、快慢指针（去重、删元素、判环）。
**要点**
- 对撞指针：**有序**数组里找一对和满足条件 → 左右往中间收，O(n) 取代 O(n²)。
- 快慢指针：原地删除/去重（写指针 + 读指针）、链表找中点/判环（Floyd）。
- 用「单调性」论证为什么移动某指针不会漏解——这是讲清楚的关键。
- edge：空数组、全相同、指针越界、奇偶长度。

### [ds-03] 滑动窗口：最长/最短子串(数组)
模板题：无重复字符最长子串、最小覆盖子串、定长窗口最大和。
**要点**
- 模式：右指针扩张纳入，违反条件时左指针收缩；维护窗口内状态（计数/哈希）。
- 变长窗口（求最长/最短满足条件）vs 定长窗口（每步进出各一个）。
- 区分「最长合法窗口」与「最短合法窗口」收缩时机不同：合法时记录 vs 非法时收缩。
- 复杂度 O(n)：每个元素最多进出窗口各一次。edge：窗口为空、全不满足。

### [ds-04] 二分查找及其变体
不止「找一个值」：找左/右边界、旋转有序数组、在「答案空间」上二分（最小可行值）。
**要点**
- 三大坑：区间定义（[l,r] vs [l,r)）要全程一致；`mid=l+(r-l)/2` 防溢出；循环终止与收缩方向。
- 找边界：用 `<` / `<=` 控制偏左偏右，找到后别立即返回、继续收缩。
- 「二分答案」：当问题是「最小的满足 X 的值」，对值域二分 + 一个 check(x) 单调判定。
- edge：空数组、单元素、目标在两端、不存在。复杂度 O(log n)。

### [ds-05] BFS vs DFS：何时用哪个
矩阵/图/树上的遍历。最短路（无权）、连通分量、层序、拓扑。
**要点**
- **无权最短路/层序 → BFS**（队列，按层扩展）；**穷举路径/连通性/回溯 → DFS**（递归或栈）。
- 必备三件套：visited 去重、邻居生成、入队/入栈时机（BFS 入队即标记，防重复入队）。
- 矩阵当图：方向数组 `dirs`，边界与越界检查。多源 BFS：初始多个点同时入队。
- 复杂度 O(V+E)。edge：空图、孤立点、自环、重边。

### [ds-06] 回溯：子集/排列/组合/棋盘
模板：选择 → 递归 → 撤销。子集、全排列、组合总和、N 皇后、单词搜索。
**要点**
- 模板：`backtrack(路径, 选择列表)`：满足终止条件收集结果，否则遍历选择→做选择→递归→撤销选择。
- 去重两招：排序后跳过同层重复（`i>start && nums[i]==nums[i-1]`）；used 数组。
- 剪枝是关键：提前判断不可能的分支（如组合总和里 num>剩余 target 就 break）。
- 复杂度通常指数级，讲清搜索树规模。edge：空输入、含重复元素、需不需要去重。

### [ds-07] 动态规划：识别 + 状态设计
怎么看出是 DP？背包、最长子序列(LIS/LCS)、编辑距离、打家劫舍、爬楼梯。
**要点**
- 识别信号：**最优子结构 + 重叠子问题**；求「最值/方案数/可行性」且选择有阶段性。
- 四步：定义状态 dp[i] 含义 → 状态转移方程 → base case → 遍历顺序（保证依赖先算）。
- 一维 vs 二维；能否滚动数组降空间。先写记忆化递归想清楚，再翻译成迭代。
- 经典：0/1 背包（逆序）、完全背包（正序）、LIS（O(n log n) 二分优化）、编辑距离。
- edge：空串、长度为 0/1、负数、容量为 0。

### [ds-08] 堆 / Top-K / 数据流中位数
Top-K 最大、第 K 大、合并 K 个有序链表、数据流求中位数。
**要点**
- Top-K 最大 → 维护**大小为 K 的小顶堆**，O(n log K)；比全排序 O(n log n) 优。
- 第 K 大也可用快速选择 quickselect 平均 O(n)。
- 数据流中位数：大顶堆存小一半 + 小顶堆存大一半，平衡两堆大小。
- 合并 K 个有序链表：堆里放 K 个表头，每次弹最小、推入其 next。
- edge：K>n、空流、奇偶个数中位数。

### [ds-09] 图：拓扑排序 / 并查集 / 最短路
课程表（环检测）、岛屿数量、网络连通、Dijkstra。
**要点**
- 拓扑排序：Kahn（入度为 0 入队，BFS）或 DFS 后序；**能否完成 = 是否有环**（拓扑结果数==节点数）。
- 并查集（Union-Find）：判连通/合并集合，路径压缩 + 按秩合并近 O(1)；适合动态连通性。
- 最短路：无权 BFS；带正权 Dijkstra（堆优化 O(E log V)）；有负权 Bellman-Ford。
- 建图方式（邻接表/矩阵）按稀疏稠密选。edge：自环、重边、非连通、有向 vs 无向。

### [ds-10] 复杂度分析与 edge case 习惯
任意题收尾：怎么报复杂度、怎么系统性地想 edge case？
**要点**
- 时间/空间都要报；递归讲清递归深度（栈空间）；摊还分析（如动态数组扩容、并查集）。
- 主定理直觉：分治 T(n)=aT(n/b)+f(n) 大致量级；别死记，能比较两个方案够用。
- edge 清单（养成习惯）：空/单元素、最大最小值、重复、负数/零、溢出、已排序/逆序、全相同。
- 沟通：写前报复杂度与思路、写后跑例子、主动说「这里假设输入非空，要不要处理？」

## 系统设计

### [sd-01] 设计短链服务（TinyURL）
长 URL → 短码，访问短码重定向。日活/QPS 自拟。
**要点**
- 澄清：读写比（读远大于写）、短码长度/字符集、是否自定义别名、过期、统计需求。
- 容量：假设写 X/s、读 100X/s，存储 = 条数 × 单条字节；估 5 年总量。
- 发码：自增 ID + Base62（短但可枚举/需协调）vs 随机 + 查重 vs 预生成发号段（KGS）。
- 数据模型：KV 即可（短码→长 URL）；读多 → 重缓存（Redis）+ CDN；DB 选 KV/分片 SQL。
- 扩展：缓存命中率、热点 key、301 vs 302、防滥用限流。讲读路径 vs 写路径。

### [sd-02] 设计新闻 Feed 流（News Feed）
关注关系下，生成用户首页 Feed。如某社交/内容产品。
**要点**
- 澄清：关注模型、Feed 排序（时间序 vs 排序）、实时性要求、媒体内容、规模（粉丝分布）。
- 两种生成：**推（fan-out on write）**写时扩散到粉丝收件箱 vs **拉（fan-out on read）**读时聚合关注者。
- 大 V 问题：纯推对千万粉丝爆炸 → **混合**：普通用户推、大 V 拉，读时合并。
- 组件：Feed 服务、收件箱存储（Redis list）、内容服务、排序服务、CDN 发媒体。
- 扩展：分片（按 user_id）、缓存、预计算 + 在线排序、一致性可放宽（最终一致）。

### [sd-03] 设计聊天 / 即时通讯系统
1对1 + 群聊，消息送达、在线状态、历史。
**要点**
- 澄清：在线状态、已读回执、群规模、消息持久化与漫游、端到端加密、推送。
- 连接层：**长连接（WebSocket）** + 连接网关；用户↔网关映射（哪台机器持有该连接）。
- 消息流：发→接入网关→消息服务→存储+路由到接收方网关→推送；离线走推送/拉取。
- 存储：消息按会话分片、时间排序；用序列号/雪花 ID 保证顺序与去重。
- 扩展：水平扩网关、Pub/Sub 路由跨机器、ACK 重试与幂等、群消息扩散策略。

### [sd-04] 设计限流器（Rate Limiter）
保护 API：每用户/每 IP 每秒 N 次。分布式环境。
**要点**
- 算法：固定窗口（边界突刺）、滑动窗口日志/计数、**令牌桶（平滑+允许突发）**、漏桶（恒定速率）。
- 单机用内存计数；分布式用 **Redis** 存计数/令牌（INCR+EXPIRE 或 Lua 原子脚本）。
- 放哪：网关/中间件层；返回 429 + Retry-After；区分维度（用户/IP/API key）。
- 权衡：精度 vs 性能 vs 内存；Redis 单点 → 分片/集群；时钟与原子性问题。
- edge：突发流量、分布式计数竞争、规则热更新。

### [sd-05] 设计「附近的人 / 附近商家」(地理位置)
给定坐标，返回附近 N 个点/在半径内的对象。
**要点**
- 澄清：更新频率（人会动）、半径/Top-N、精度、读写比、规模。
- 空间索引：**Geohash**（经纬度编码成字符串，前缀近似邻近）或 QuadTree、Google S2。
- 查询：算目标点 geohash → 查同前缀 + 8 个相邻格 → 精确算距离过滤排序。
- 存储：Redis GEO（底层 geohash + 有序集合）或带空间索引的 DB；热点城市分片。
- 扩展：边界格漏查（查邻格补偿）、动态对象的更新成本、按城市/网格分片。

### [sd-06] 设计方法论：从需求澄清到扩展(任意题通用)
面试官给一句模糊需求，你的标准推进流程是什么？
**要点**
- 流程：①需求澄清（功能/非功能/规模）②容量估算（QPS、存储、带宽）③API 设计 ④数据模型 ⑤高层组件图 ⑥逐组件深入 ⑦扩展与权衡。
- 非功能需求最值钱：可用性 vs 一致性、延迟、读写比、一致性级别——先框定再设计。
- 扩展工具箱：缓存（旁路/读穿/写回）、分片/sharding（按 key/范围/一致性哈希）、复制（主从/多主）、负载均衡、消息队列削峰解耦。
- **CAP**：分区时在一致性与可用性间取舍；多数互联网系统选 AP + 最终一致。
- 一直「想清楚再说」「主动报权衡」，别一上来画细节；时间分配先广后深。

## OOD/LLD

### [oo-01] 设计停车场（Parking Lot）
多种车位（小/中/大）、入场出场、计费。面向对象怎么建模？
**要点**
- 找名词→类：ParkingLot、Level/Floor、ParkingSpot（含尺寸枚举）、Vehicle（抽象，子类 Car/Bus/Motorcycle）、Ticket。
- 找动词→方法：park()、leave()、findSpot()、calculateFee()。
- 多态：不同车型匹配车位规则用多态/策略；计费策略可替换（按时/按次）。
- 关注点分离：分配车位、计费、出入口控制各自单一职责。
- 讲清扩展性：加新车型/新计费规则时改动最小（开闭原则）。

### [oo-02] 设计电梯调度系统（Elevator）
多部电梯、楼层请求、调度策略。
**要点**
- 类：ElevatorSystem（调度器）、Elevator（状态：当前层/方向/门）、Request（楼层/方向）、用枚举表示方向与状态。
- 状态机：Idle/MovingUp/MovingDown/DoorOpen；请求队列与方向合并（同向顺路接）。
- 调度策略可插拔（最近电梯 / SCAN 扫描算法）→ **策略模式**，便于换算法。
- 并发：多请求并发到达，调度器线程安全；内部请求 vs 外部呼叫区分。
- 讲清「请求如何分配给哪部电梯」是核心，给一个合理的启发式即可。

### [oo-03] 设计图书馆 / 借还书系统（Library）
书目、会员、借阅、归还、罚款、预约。
**要点**
- 类：Book / BookItem（同一书多份）、Member、Catalog（按题名/作者检索）、Lending（借阅记录）、Fine。
- 关系：一个 Book 多个 BookItem；Member 与 BookItem 多对多（通过借阅记录）；预约队列。
- 规则封装：最大借阅数、借期、超期罚款——放在专门的规则/策略对象，别散落。
- 用例：checkout、return、reserve、renew、search；状态：Available/Loaned/Reserved/Lost。
- 体现 SOLID：检索、借阅、计费各单一职责，依赖抽象（如通知接口）。

### [oo-04] SOLID 原则 + 常用设计模式
说说 SOLID 五原则，各举一个工程例子；工厂/策略/观察者/单例分别解决什么？
**要点**
- **SOLID**：S 单一职责、O 开闭（对扩展开放对修改关闭）、L 里氏替换、I 接口隔离、D 依赖倒置（依赖抽象非具体）。
- 工厂：把「创建对象」与「使用对象」解耦，新增类型不改调用方。
- 策略：把一族可互换算法封装、运行时切换（如上面的调度/计费策略）。
- 观察者：一对多通知，发布-订阅解耦（事件系统、UI 更新）。
- 单例：全局唯一实例（配置/连接池）；注意线程安全（双检锁/静态内部类/枚举）与可测试性争议。

### [oo-05] OOD 中的并发要点
设计有共享状态的对象（计数器、连接池、生产者-消费者）时怎么保证线程安全？
**要点**
- 共享可变状态是万恶之源：能不共享就不共享（不可变对象、线程封闭）。
- 同步手段：锁（互斥/读写锁）、原子变量（CAS）、并发容器、信号量/阻塞队列。
- 经典模型：生产者-消费者用阻塞队列解耦；连接池用信号量限并发 + 借还。
- 死锁四条件与预防：固定加锁顺序、超时、避免嵌套锁；讲清你的锁粒度权衡。
- 面试讲清「哪些状态被多线程读写、用什么保护、为什么这个粒度」。

## 行为面

### [bh-01] STAR 框架与一个高 ownership 故事
讲一个你主动扛下、端到端负责并交付的项目。
**要点**
- **STAR**：Situation 背景一句话、Task 你的职责、Action **重点在你做了什么/你的判断**、Result 量化结果。
- Ownership 信号：主动发现问题、定义方案、推动落地、对结果负责（包括踩坑后兜底）。
- 80% 篇幅在 Action 与你的决策，别花太多在背景；用「我」而非「我们」突出个人贡献。
- 结果量化（性能提升 X%、故障减少、上线时间）；没数据就给可信的定性影响。
- 准备 2–3 个可复用的强故事，按问题角度复述同一个故事的不同侧面。

### [bh-02] 技术冲突 / 与同事意见分歧
讲一次你和同事/leader 在技术方案上有分歧，怎么处理的。
**要点**
- 结构：分歧点是什么 → 你怎么理解对方立场 → 用什么客观依据推进（数据/原型/权衡表）。
- 体现：先听懂对方、对事不对人、用证据而非嗓门、必要时小成本验证（spike/POC）。
- 结局两类都行：你被说服（展示开放）或你说服了对方（展示影响力），关键是**理性达成共识**。
- 避免：贬低对方、纯靠职级压人、为赢而赢。强调团队最终结果。

### [bh-03] 跨团队协作 / 推动依赖方
讲一次需要别的团队配合（你没有管理权）才能交付的事。
**要点**
- 难点：没有直接权限、对方优先级不同、沟通成本。
- 行动：讲清对对方的价值（why should they care）、对齐目标、明确接口/时间线、建立信任与定期同步。
- 影响力来自：清晰沟通 + 互惠 + 可靠交付，而非权威。
- 结果：交付 + 关系，最好留下可复用的协作机制/流程。

### [bh-04] 失败 / 线上事故复盘
讲一次你的失败、bug 或线上故障，学到了什么。
**要点**
- 选一个**真实、你负主要责任**的失败（别选「我太追求完美」这种假失败）。
- 结构：发生了什么 → 你的责任（不甩锅）→ 当时怎么止血 → **根因 + 长期改进** → 之后如何避免复发。
- 体现成长型思维：把教训制度化（加监控/测试/review/runbook）。
- 收尾给「现在再来一次我会怎么做」，展示反思深度。

### [bh-05] Tell Me About Yourself / 为什么换工作
~60–90 秒自我介绍 + 为什么找下一站、为什么这家。
**要点**
- 结构：现在定位（角色/领域/最近一个亮点）→ 一条主线串起经历（别流水账）→ 为什么找下一站（正向叙事）→ 为什么这家/这个组。
- 为什么离开：永远正向——「想要 X 成长/影响/方向」而非抱怨现东家。
- 为什么这家：做过功课，连接到对方业务/技术/产品的具体点。
- 控制时长、留钩子让面试官追问你想讲的强项。
