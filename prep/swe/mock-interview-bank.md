# Mock 面试题库 + 自评表 — Software Engineer

> 用 Claude 当面试官跑全真 mock，或自己录音 mock 后复盘。题目可从 [question-bank.md](question-bank.md) 抽，也可让 Claude 现出新题。
> 用法：选一套 → 计时 → 出声/写完 → 按下方自评表打分 → 把「最大坑」回填 [practice-log.md](practice-log.md)。

## 如何跑一场全真 mock（推荐 60–75 分钟）

1. **设定角色**：让 Claude「扮演 X 公司面试官，出一道中等 coding 题，只给题面，逐步追问，最后给反馈」。
2. **限时真做**：coding 25–35 分钟 / system design 35–45 分钟；**全程出声讲**，别停下来内心独白。
3. **要求 follow-up**：好面试官会加约束、加规模、问复杂度优化、问 edge case——让 Claude 也这么逼你。
4. **结束才看反馈**：自己先复述「我哪里卡了、哪里讲糊了」，再看 Claude 的硬伤清单与更优解。
5. **复盘落库**：把 1 个最大坑 + 1 个下次改的动作写进 [practice-log.md](practice-log.md)。

## A. Coding（DS&A）— 单题 25–35 分钟

跑一道中等题（参考 [question-bank.md](question-bank.md) 的 `ds-*`），评分看：

- [ ] 答前澄清输入/输出/约束/edge（没澄清就扣分）。
- [ ] 先讲思路与复杂度，再动手写。
- [ ] 代码结构清晰、命名清楚、边写边讲。
- [ ] 写完主动跑一个例子验证 + 列 edge case。
- [ ] 被追问「能更快吗 / 空间能省吗 / 输入变大怎么办」能应对。

## B. System Design — 35–45 分钟

跑一道（参考 `sd-*`），评分看：

- [ ] 先花时间澄清功能/非功能需求与规模，不急着画。
- [ ] 给出粗略容量估算（QPS / 存储 / 带宽）。
- [ ] 画出高层组件 + 数据流，再逐组件深入。
- [ ] 主动给扩展手段与**取舍**（缓存/分片/复制/一致性/瓶颈）。
- [ ] 识别并讨论瓶颈/单点/热点，给缓解方案。

## C. OOD / LLD — 25–35 分钟

跑一道（参考 `oo-*`），评分看：

- [ ] 从需求抽出核心类/职责，画类关系。
- [ ] 体现 SOLID（尤其单一职责、开闭、依赖抽象）。
- [ ] 恰当用 1–2 个设计模式并说明为什么。
- [ ] 讨论扩展性（加新类型/新规则改动最小）与（如相关）并发。

## D. Behavioral — 20–30 分钟，3–4 题

用你定稿的 STAR 故事（见 [behavioral/README.md](behavioral/README.md)）跑：ownership / 冲突 / 跨团队 / 失败 各一题，评分看：

- [ ] STAR 结构清楚，Action 占大头、突出「我」的判断。
- [ ] 结果量化或可信定性。
- [ ] 不甩锅、不假大空、对事不对人。
- [ ] 同一故事能按不同问题角度复述。
