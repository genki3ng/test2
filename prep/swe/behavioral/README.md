# 行为面（Behavioral）— Software Engineer

> 故事正文用 **英文**（面试对外）。SWE 重点：**技术 ownership、技术冲突/分歧、跨团队协作、失败复盘、影响力**。资深岗更重跨团队领导与影响力。
> 这是一个**空模板**：用下面的结构和提示，让 Claude 把你自己的经历填成 STAR 故事。**故事质量靠你自己挖，框架只是壳。**

## STAR 框架（每个故事都这么搭）

- **Situation**：一句话交代背景与问题（别铺垫太久）。
- **Task**：你的具体职责——你要解决什么（用「我」）。
- **Action**：**重点，占 ~80%**——你做了什么、你的判断/权衡/沟通；突出个人贡献而非「我们」。
- **Result**：量化结果（性能 +X%、故障 -Y%、上线提前 Z）；没硬数据就给可信定性影响 + 学到什么。

> 一个好故事能从多个角度复述：同一个项目，问 ownership 讲决策与交付，问冲突讲分歧处理，问失败讲踩过的坑。准备 **2–3 个强故事**覆盖多数问题。

## 常见问题清单（→ 映射到上面故事）

- Tell me about yourself（见上方 SWE 版电梯陈述）
- 最有挑战/最自豪的技术项目、一次你端到端 own 的事 → **Story 1**
- 一次和同事/leader 技术意见不合、怎么解决 → **Story 2**
- 一次推动跨团队/跨职能、说服没有管理权的人 → **Story 3**
- 一次失败 / 线上事故 / 写出大 bug、学到什么 → **Story 4**
- 一次在 deadline / 模糊需求 / 技术债下做取舍 → **Story 1 或 4**
- 为什么离开 / 为什么这家 → 提前备正向叙事的定制版

## 答题原则（自检）

- [ ] STAR 结构清楚，Action 占大头、突出「我」。
- [ ] 结果尽量量化；选**真实**失败、不甩锅、不假大空。
- [ ] 冲突类：对事不对人、用证据而非职级/嗓门、强调团队结果。
- [ ] 失败类：体现根因分析 + 把教训制度化（成长型思维）。
- [ ] 控制时长、有钩子引导面试官追问你的强项。
