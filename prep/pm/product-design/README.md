# 产品设计 / Product Sense（速查 + study guide）

> 最高频也最能拉开差距的一轮。考的是 **用户共情 + 结构化思维 + 取舍判断**，没有标准答案。
> 练法：从 [../question-bank.md](../question-bank.md) 抽 pd 系列题，出声讲 5 分钟，对照下面框架查漏。

## 核心框架：CIRCLES

| 步 | 含义 | 你要做什么 |
|---|---|---|
| **C**omprehend | 理解情境 | 澄清：什么产品/功能、什么平台、为什么现在问这个 |
| **I**dentify customer | 圈定用户 | 列用户画像，**挑一个高价值人群聚焦**（规模 × 痛感 × 战略契合） |
| **R**eport needs | 列需求/痛点 | 该人群的 JTBD 与未满足痛点，最好有 1–2 条具体洞察 |
| **C**ut through prioritization | 优先级 | 痛点/人群太多时，按价值排序，明说聚焦哪个 |
| **L**ist solutions | 列方案 | 头脑风暴 ≥3 个方案，别只想一个 |
| **E**valuate trade-offs | 评估取舍 | 用影响 × 成本（或 RICE）排序，**推荐 1 个**并讲清为什么 |
| **S**ummarize | 收尾 | 复述推荐 + 成功指标 + 风险/护栏 + 验证方式 |

> 记不住全称没关系，**骨架就三段**：澄清+定用户 → 痛点+方案 → 取舍+指标。

## 万能开场（澄清四问）

1. 这个产品/功能**为谁**服务？（圈用户）
2. 我们想达成什么**目标**？（增长 / 留存 / 参与 / 变现）
3. 处在什么**阶段**？（0→1 找 PMF vs 成熟期优化）
4. 有什么**约束**？（平台、合规、资源）

## 用户洞察与痛点（怎么显得"真懂用户"）

- 画 **persona**：不只人口属性，要场景 + 动机 + 当前怎么凑合解决（workaround）。
- 用 **JTBD** 提问："用户雇这个产品来完成什么任务？"——挖功能背后的真实目的。
- 画 **用户旅程**，标出摩擦点 / 流失点，下手处往往就在断点。
- 说 1–2 条**反直觉或具体的洞察**（"其实他们不是为 X，而是为 Y"），比泛泛列需求更打动人。

## 方案取舍与优先级

- 永远给 **≥3 个方案**再收敛，展示发散能力；再用 **影响 × 成本 / 努力** 排序。
- 推荐时讲清**为什么不是另外两个**（机会成本），这比只夸推荐方案更有说服力。
- **MVP 思维**：先做能验证核心假设的最小切片，而非一步到位。
- 主动提**风险与护栏**：这个方案可能伤什么指标、怎么兜底。

## 常见题型 → 起手式

| 题型 | 起手 |
|---|---|
| "改进产品 X" | CIRCLES：先问改的目标，再聚焦一个人群的一个痛点 |
| "为某人群设计 Y" | 先共情该人群独特约束/JTBD，再 MVP |
| "0→1 设计新产品" | 圈早期用户 + 解决鸡生蛋 + 列假设与低成本验证 |
| "砍功能 / 做减法" | 用数据分"重度依赖 vs 全员低频"，谈迁移成本 |
| "你最喜欢的产品" | 用户价值 + 商业模式 + 护城河三层 + 一个不足 |

## 反模式（面试官最烦这些）

- 不澄清就开冲、一上来堆功能清单。
- 不聚焦人群，"所有用户都想要"。
- 只谈 UI / 漂亮，不挖底层需求。
- 给方案不排序、不推荐、不给成功指标。
- 忽略商业目标，纯做"用户许愿池"。
