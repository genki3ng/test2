## 产品设计

### [pd-01] 改进一个你常用的产品
经典开放题（"How would you improve X?"）。X 可换成地图、播客 app、外卖、企业 IM 等。
**要点**
- 别急着说功能：先 **CIRCLES** 起手——澄清（C）+ 圈定用户（I）。问清"为谁改 / 改什么目标（增长 vs 留存 vs 变现）"。
- 列用户画像 + 各自核心痛点，**挑一个高价值人群聚焦**，说清为什么是它（规模 × 痛感 × 与业务目标契合）。
- 针对痛点头脑风暴 ≥3 个方案，按 **影响 × 成本**（或 RICE）排序，明确推荐 1 个并说取舍。
- 收尾给成功指标 + 你会怎么验证（灰度 / A/B），主动提一个风险或护栏指标。
- 反模式：上来堆 5 个零散功能、不聚焦人群、不给指标。

### [pd-02] 为「某用户群」设计一个产品 / 功能
如：为视障用户设计导航、为老年人设计支付、为自由职业者设计记账。
**要点**
- 先共情：该人群的**场景、约束、未被满足的 job-to-be-done** 是什么；最好说 1–2 条具体洞察而非泛泛。
- 框定一个最痛的用例聚焦，避免"什么都做"。
- 给 2–3 个方案 + 推荐 1 个，讲清为什么先做它（MVP 思路：最小可验证）。
- 谈可达性/无障碍/隐私等该人群特有约束（这类题常考你是否真共情）。
- 指标：怎么衡量"解决了痛点"（采用率 + 任务完成率 + 满意度）。

### [pd-03] 设计一个你没做过领域的产品（0→1）
如"为社区医院设计预约系统""设计一个二手书交易平台"。
**要点**
- 澄清商业目标与成功定义；圈定**最早期目标用户**（早期不贪多）。
- 画核心用户旅程，找断点 / 摩擦最大处下手。
- MVP：能验证核心假设的最小切片是什么；先解决**鸡生蛋**（双边市场先补供给还是需求）。
- 列关键风险与假设，给"如何低成本验证"（着陆页 / 访谈 / 绿野仙踪法）。
- 指标分层：激活漏斗 → 留存 → 变现，明确北极星雏形。

### [pd-04] 最喜欢的产品是什么、为什么 / 它差在哪
**要点**
- 选一个你真懂的产品；讲清它服务的 **JTBD** 和做对的 1–2 个关键设计决策。
- 用"用户价值 + 商业模式 + 护城河"三层解释它为何成功，体现产品判断力。
- 主动指出它**最大的一个不足**和你会怎么改——展示批判性思维，不当粉丝。
- 避免只夸 UI；要谈底层用户需求与权衡。

### [pd-05] 给现有产品做减法 / 砍功能
**要点**
- 区分"被少数重度用户依赖"vs"全员低频"——看数据（使用率、留存贡献、支撑成本）。
- 砍的标准：维护成本高 + 价值低 + 不在战略主线；保留要看是否服务核心 JTBD。
- 谈迁移与沟通成本：怎么不激怒现有用户（灰度下线、提供替代）。
- 强调"少即是多"对聚焦与体验的价值，但用数据而非直觉拍板。

## 指标与分析

### [me-01] 为一个新功能定义成功指标
**要点**
- 先澄清：功能是什么、目标用户、所处生命周期阶段、背后的业务目标。
- 指标分层：**北极星**（1 个，代表长期价值）+ 输入/驱动指标 + **护栏指标**（防伤害，如留存、申诉率、时延）。
- 北极星三原则：与长期价值一致、能被该功能影响、不易被刷（别选虚荣指标）。
- 区分采用（adoption）、参与（engagement）、留存（retention）、变现，按功能目标取主指标。
- 收尾：指标冲突如何权衡，下一步常接 A/B 验证因果。

### [me-02] 一个核心指标掉了 X%，怎么排查
如"DAU 上周跌了 5%""下单转化率掉了""留存下滑"。
**要点**
- 先澄清+止血：跌了多少、什么时候开始、是突变还是渐变、波及范围。
- **先排除数据问题**：埋点 / 日志 / 口径变更 / 节假日季节性 / 重大外部事件。
- 结构化拆解：按维度分群（地区 / 平台 / 新老用户 / 版本 / 渠道）定位是**普跌还是局部**。
- 沿**漏斗**拆（曝光→点击→转化→完成）看哪一环掉；内因（发版/改版/价格）vs 外因（竞品/政策/大盘）。
- 收敛到根因假设 + 验证方式 + 短期缓解 vs 长期修复，主动说"我会先看哪张图"。

### [me-03] 估算题（guesstimate）
如"某城市一天卖多少杯咖啡""某 app 一天上传多少张图"。
**要点**
- 大声说**思路结构**比精确更重要：自上而下（人口 × 渗透率 × 频次）或自下而上（单店 × 店数）。
- 显式列假设并标在合理量级（人口、渗透率、频次、客单价），数字取整好算。
- 分段估：分人群 / 分时段 / 分场景，避免一个系数拍死。
- 做 sanity check（量级对不对、能否换个路径交叉验证），说清最敏感的假设。
- 把估算接回业务："如果用于定容量 / 估市场规模，我会再校准 X。"

### [me-04] 量化一个难量化的东西
如"如何衡量内容质量 / 用户信任 / 社区健康度"。
**要点**
- 先定义概念：把抽象拆成可观测的**代理指标**（proxy），说清每个代理为何相关。
- 组合多个信号成指数，避免单一指标被钻空子（如"质量"= 完播 + 举报率 + 复访 + 人工抽检）。
- 谈代理指标的**失真风险**（Goodhart 定律：一被当 KPI 就被刷）与校正办法。
- 给可落地的衡量方案 + 怎么验证它真的代表了那个抽象目标。

### [me-05] 量化一个产品取舍（trade-off）
如"加更多广告会提收入但伤体验，怎么定量决策"。
**要点**
- 把两边都**指标化**：收益侧（增量收入/参与）vs 代价侧（留存、满意度、长期 LTV）。
- 用同一货币或同一时间窗对齐（短期收入 vs 长期留存折现），讲清比较口径。
- 设阈值 / 护栏：留存或申诉跌破某线就不上；用 A/B 量化净效应。
- 给决策建议时讲清你**最看重的长期指标**，不被短期数字绑架。

## 战略与执行

### [st-01] 某公司该不该进入「某新市场 / 新业务」
如"地图公司要不要做打车""IM 要不要做电商"。
**要点**
- 框架：市场吸引力（规模/增速/竞争）× 我们的**制胜权利**（right to win：现有资产、用户、数据、渠道）。
- 分析现有玩家与差异化空间，找我们独有的 unfair advantage。
- 给清晰**结论**（进 / 不进 / 试点），列关键假设和最大风险。
- 谈进入方式：自建 vs 收购 vs 合作；MVP 试点先验证哪个假设。
- 体现 IC6 高度：把它接回公司整体战略与资源分配，不只看单点。

### [st-02] 为一个产品做竞品分析 / 应对强竞对
**要点**
- 选维度对比（目标用户、核心价值、商业模式、增长引擎、护城河），别只比功能清单。
- 找我们的**差异化定位**和对手的结构性弱点；判断哪些功能要跟、哪些不值得跟。
- 谈护城河：网络效应 / 转换成本 / 规模经济 / 数据，我们能建哪种。
- 给行动建议：守住核心 + 在一个差异点上做深，而非全面对标。

### [st-03] 给一个产品定 GTM（上市策略）/ 冷启动
**要点**
- 澄清目标（市场份额？营收？教育市场？）与目标细分人群。
- 定位与价值主张：一句话说清"为谁、解决什么、凭什么比替代品好"。
- 渠道与获客：哪些渠道触达该人群、CAC/LTV 是否成立；双边市场先解决冷启动（补贴哪边、种子供给）。
- 定价模型与里程碑、成功指标（激活/留存/口碑），以及失败如何快速止损。

### [st-04] 怎么给团队做路线图 / 排优先级
**要点**
- 先有北极星与季度目标（OKR），让优先级**服务于目标**而非拍脑袋。
- 量化排序：**RICE**（Reach × Impact × Confidence ÷ Effort）或价值-成本矩阵；讲清打分依据。
- 平衡：增长 vs 体验 vs 技术债 vs 平台投资；留 buffer 给突发与维护。
- 对齐与沟通：跟 Eng/Design/数据/业务方拉齐，明确"不做什么"同样重要。
- 谈如何应对中途变化（数据/市场变了如何重排）。

### [st-05] 如何无授权推动一个跨职能项目落地
偏执行/影响力，常与行为面交叉。
**要点**
- 先建**共识与北极星**：让各方看到对其目标的价值，用数据和用户故事说服而非靠职权。
- 厘清 RACI / 干系人地图，找关键盟友与潜在阻力，逐个对齐。
- 拆里程碑、定 owner、建节奏（站会/周报），把模糊目标变成可追踪任务。
- 主动暴露风险与依赖，遇阻塞时升级有度；用早期小胜建立信任。
- 收尾讲影响与复盘——体现 ownership 与领导力。

## 行为面

### [bh-01] 讲一个你推动的最有影响力的项目（TMAY / 招牌故事）
**要点**
- **STAR**：Situation 背景、Task 你的目标/职责、Action 你具体做了什么、Result 量化结果。
- 突出"**你**做了什么"而非团队泛泛；体现产品判断、跨职能领导、数据驱动决策。
- 结果量化（指标提升 X%、影响 N 用户/营收），并说清你如何归因到自己的决策。
- 准备一个"如果重来会怎么改"的反思，展示成长心态。

### [bh-02] 一次你在没有正式授权下影响他人 / 推动决策
**要点**
- 场景里你**没有命令权**（跨团队、对上、对合作方），靠数据/愿景/关系推动。
- Action：怎么倾听对方诉求、找共同目标、用证据说服、做必要妥协。
- Result：达成了什么共识与产出；体现"用影响力而非职权"的领导力。
- 这是 IC6/高级 PM 高频信号题，准备 1 个强故事。

### [bh-03] 一次冲突 / 与人意见严重不合，怎么处理
如与工程对技术方案、与设计对方向、与上级对优先级。
**要点**
- 描述分歧本质（不是人身，是观点/优先级冲突）。
- Action：先理解对方立场与背后约束，用数据/用户证据对齐目标，必要时做实验让数据说话。
- 展示成熟度：能为大局让步、也能据理力争；对事不对人。
- Result + 学到什么：关系是否维护好、决策是否更优。

### [bh-04] 一次失败 / 做错的决策，怎么复盘
**要点**
- 选一个**真失败**（产品没成、指标没达、判断错了），别选伪失败。
- 诚实讲你的责任份额（owner 心态，不甩锅）。
- 重点在**反思与改变**：你从中学到什么、之后怎么做不一样、有无验证改进有效。
- 结尾积极：把失败转成可迁移的方法论。

### [bh-05] 一次向上沟通 / 说服领导改变方向
**要点**
- 背景：你看到领导可能没看到的信号（数据、用户、市场）。
- Action：怎么准备证据、选时机、用对方关心的目标和语言沟通、给可选项而非只抱怨。
- 处理"领导不同意"：先 disagree and commit 还是继续争取，讲清判断。
- Result：决策是否调整、信任是否建立；体现影响上级的成熟度。
