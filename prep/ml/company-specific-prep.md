# 各公司定制题：面试重点 + 我的角度 — Machine Learning Engineer

> 模板占位 —— 每家目标公司开一段，用 Claude 生成「业务域 → ML 在哪创造价值 → 面试重点 → 可能问 + 我的角度 → 注意」。
> 用法：投/面某家前过一遍对应段；面后把真实题回填对应 [pipeline/companies/*.md](../../pipeline/companies/)。
> 占位公司名为虚构示例，请替换成你的真实目标公司。

---

## Northwind（示例：电商 / marketplace）

业务域：双边电商平台，ML 主要用于搜索排序、推荐（「猜你喜欢」）、广告、欺诈检测。

- **面试重点**：召回 + 精排两阶段、多目标排序（点击/转化/GMV）、冷启动、训练-服务一致。
- **可能问 + 我的角度**：
  - 「设计商品推荐系统」→ 用 [ms-01]/[ms-06] 骨架，强调 marketplace 双边（买家体验 + 卖家曝光公平）与多目标融合。
  - 「转化率预估线上掉了怎么查」→ 训练-服务 skew（[ms-03]）+ 分布漂移 + 上游数据变更三条线排查。
- **注意**：业务指标连接（GMV / 转化 / 留存）和护栏（卖家公平、用户体验），别只谈模型精度。

## Vertex Cloud（示例：云 / 平台 / Infra ML）

业务域：云服务商，ML 偏平台与基础设施（特征平台、模型服务、大规模训练、AutoML、异常检测）。

- **面试重点**：特征平台设计、模型上线/监控/回滚、大规模训练与服务、系统可靠性。
- **可能问 + 我的角度**：
  - 「设计一个 feature store」→ 用 [ms-02]，强调离线/在线双存储、point-in-time join、版本与血缘、监控。
  - 「模型服务怎么做灰度与回滚」→ 用 [ms-05]，金丝雀/影子流量 + 分层监控 + 触发阈值回滚。
- **注意**：偏工程系统性（可靠性、可观测性、扩展性）而非单纯建模深度。

## Helios Media（示例：社交 / 内容 / 信息流）

业务域：内容社交平台，ML 用于信息流推荐、内容理解（NLP/CV）、内容审核、增长。

- **面试重点**：信息流排序、多目标（停留/互动/留存）、内容理解 embedding、内容安全、A/B。
- **可能问 + 我的角度**：
  - 「设计信息流推荐」→ 用 [ms-01]，多目标融合 + 多样性重排 + 新内容冷启动 + 护栏（举报/负反馈）。
  - 「怎么离线评估 + 在线验证一个排序改动」→ 用 [ms-04]，离线 NDCG/AUC → 灰度 → A/B 看核心指标 + 护栏。
- **注意**：长期价值与护栏（别为短期互动牺牲留存/健康度），强调实验与监控。
