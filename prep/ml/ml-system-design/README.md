# ML System Design — MLE 的胜负手

> 目标：给一个真实场景，35 分钟内走通「澄清 → 数据/特征 → 召回+精排 → 评估 → A/B → 上线监控/回滚」，并在每一步讲取舍。题库见 [../question-bank.md](../question-bank.md) 的「ML 系统设计」。

## 万能答题框架（背熟，套任何场景）

1. **澄清需求（别跳！）**
   - 业务目标是什么？优化点击 / 时长 / 转化 / 留存 / GMV？多目标怎么权衡？
   - 规模：item/user 量级、QPS、延迟预算（端到端多少 ms）？
   - 约束：冷启动、内容/合规、实时性要求、训练数据可得性。
2. **数据与标签**
   - 正负样本怎么定义（点击=正？曝光未点=负？隐式反馈）？标签延迟与噪声？
   - 训练数据来源、采样、时间切分（防泄漏）。
3. **特征**
   - 用户画像 / item 内容与统计 / 上下文 / 交叉 / 序列特征 / embedding。
   - 强调**离线-在线特征一致**与新鲜度（接 feature store）。
4. **模型架构**
   - 通常**两阶段**：召回（双塔 + ANN / 协同过滤 / 多路并集）→ 精排（GBDT / DNN / 多任务）。
   - 多目标：加权融合 `score = Σ wᵢ·pᵢ` 或多任务；上层可加重排（多样性/打散/商业规则）。
5. **评估**
   - 离线：AUC / NDCG / Recall@K / LogLoss；说清离线-在线 gap。
   - 在线：A/B 核心指标 + 护栏；先查 SRM 再读结果。
6. **上线与监控**
   - 灰度/金丝雀/影子 → A/B → 全量；分层监控（系统/数据/模型）+ 回滚阈值。

## 必懂概念（cheatsheet）

| 概念 | 一句话 | 面试落点 |
|---|---|---|
| **召回 + 精排** | 粗筛（亿→千，快/便宜/高召回）+ 精算（重模型高精度） | 为什么分两阶段、各层 Recall 与延迟取舍 |
| **双塔 + ANN** | 用户塔/item 塔各出 embedding，离线建 ANN 索引（HNSW/IVF）在线检索 | 召回主力、可预计算 item 向量 |
| **多目标排序** | 多个预估目标加权或多任务融合 | 权重怎么定（业务 + 实验）、目标冲突 |
| **特征平台（feature store）** | 离线+在线双存储，同一份定义生成两边 | 解决训练-服务口径不一致 |
| **训练-服务 skew** | 训练与线上特征/分布不一致 → 线上掉点 | 三类来源 + 怎么防（见下） |
| **point-in-time join** | 取标签时刻前可得的特征，防未来信息泄漏 | 离线训练正确性的关键 |
| **离线 vs 在线评估** | 离线快便宜有 gap，在线 A/B 才算数 | 离线选模 → 灰度 → A/B 验证 |
| **calibration** | 预测概率是否接近真实频率 | 排序对但概率偏 → 影响出价/阈值 |

## 训练-服务偏斜（高频追问）

- **三类来源**：① 特征工程两套代码口径漂；② 数据分布漂移；③ 时间穿越/标签泄漏。
- **防**：特征逻辑单一来源（共享库/feature store）、point-in-time join、影子流量回放校验、线上线下特征分布比对。
- **诊断顺序**：先确认「特征一致性」（同一请求线上线下打分是否一致）→ 再看「分布漂移」（监控特征/预测分布）。

## 上线监控与回滚（高频追问）

- **上线方式**：影子模式（只打分不生效，对比线上）→ 金丝雀灰度（1%→10%→100%）→ A/B 分桶。
- **监控分层**：系统（QPS/延迟/错误率）｜数据（特征缺失、分布漂移）｜模型（预测分布、calibration、核心业务指标）。
- **回滚**：预设触发阈值（核心指标跌 X% / 护栏破线 / 错误率飙升）→ 一键切回上个稳定版本；模型 + 特征都要可版本化回滚。

## 常见场景 + 关键差异

| 场景 | 别忘了强调 |
|---|---|
| 信息流 / 内容推荐 | 多目标、多样性重排、冷启动、护栏（举报/负反馈） |
| 搜索排序 | query 理解、相关性 + 行为信号、位置偏差 |
| 广告 / 出价 | calibration（概率要准）、pCTR×bid、预算约束 |
| 欺诈 / 异常检测 | 类别极不平衡、低延迟、可解释、对抗演化 |
| 特征平台 | 离线/在线一致、版本血缘、TTL、监控 |
