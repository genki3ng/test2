# Behavioral 行为面 — MLE 版

> 目标：用 STAR 把经历讲成 2 分钟有结构的故事，体现 ownership、跨职能影响、对线上结果负责。题库见 [../question-bank.md](../question-bank.md) 的「行为面」。

## STAR 框架

- **S**ituation：背景一句带过（别铺垫太久）。
- **T**ask：你的目标/职责是什么。
- **A**ction：**重头戏**——你具体做了什么、为什么这样选（讲取舍）。用「我」讲清个人贡献。
- **R**esult：量化结果（指标涨跌、延迟/成本下降、覆盖面）+ 学到什么。

要点：重点在 Action 和量化的 Result；提冲突/失败/取舍更可信，别只报喜。

## 准备 5–6 个可复用故事（MLE 视角）

按这些主题各备 1 个，能灵活映射到多数问题：

| 故事主题 | MLE 常见素材 | 映射的常见问题 |
|---|---|---|
| **模型/系统上线** | 把某模型从离线做到线上并拿到指标提升 | 「最有影响力的项目」「端到端 own 的事」 |
| **救火 / 事故复盘** | 线上指标骤降、训练-服务 skew、数据漂移 | 「最难的 bug / 事故」「失败经历」 |
| **跨团队协作** | 与 PM/数据/平台/对端工程对齐口径与目标 | 「跨职能合作」「说服别人」 |
| **冲突 / 取舍** | 模型精度 vs 延迟、短期指标 vs 长期健康 | 「意见不合怎么办」「艰难取舍」 |
| **失败 / 教训** | 上线没涨、方向押错、低估数据问题 | 「失败」「如果重来」 |
| **影响力 / 主动性** | 推动监控体系、特征复用、流程改进 | 「超出本职」「Staff 级影响力」 |

## 模型上线事故复盘（MLE 高频，单列）

被问到「讲一次出事故」时，按这个讲：

1. **怎么发现**：监控/告警还是用户反馈？（能说「我们有监控提前发现」更好）
2. **影响范围 + 止血**：影响多少流量/指标，第一时间做了什么（回滚 / 降级 / 切规则）。
3. **根因**：常见为训练-服务 skew、上游数据变更、标签泄漏、分布漂移、发布配置错——讲清你怎么定位。
4. **复盘产出**：blameless、根因 + 行动项（加监控/加测试/改流程），并落实防复发。
5. **你的角色与收获**：主动承担、推动系统性改进，而非甩锅。

## 跨团队协作怎么讲

- 讲清利益相关方、目标/口径不一致在哪、你如何对齐（数据 / 文档 / 共识机制 / 单一信息源）。
- 处理冲突：先理解对方约束 → 找共同目标 → 用数据/原型做可量化取舍，而非各执一词。
- 结果落到「协作机制改善 + 项目推进」，并反思下次怎么更早对齐。

## Ownership / 模糊与优先级

- **Ownership**：超出本职主动补位、对结果负责到底、主动暴露风险而非藏问题。
- **模糊任务**：先澄清目标与成功标准 → 拆里程碑 → 做小 spike 减少不确定性。
- **优先级冲突**：按影响/成本/紧急度排序，与相关方对齐，明确「先不做什么」并说理由。

## 常被问的题（练答）

- 介绍一下你自己 / TMAY（2 分钟，对齐目标岗位）。
- 你最有影响力 / 最自豪的 ML 项目。
- 一次模型/系统上线出事故，怎么处置和复盘。
- 一次和 PM/数据/平台目标不一致、你怎么对齐。
- 一次失败的 ML 项目，学到什么。
- 一次你 own 了职责外的问题。
- 为什么想离开现在的岗位 / 为什么对我们感兴趣。

## 练习方式

- 抽 [../question-bank.md](../question-bank.md) 的 bh-0x，出声讲，控制在 2 分钟内。
- 让 Claude 按目标公司价值观追问 follow-up（「你当时为什么不先做 X」「如果重来怎么做」）。
- 录下来回听：是否啰嗦、有没有量化结果、是不是「我」而非「我们」。
