## 算法与数据结构

### [ds-01] 两数之和 / 子数组和：哈希把 O(n²) 降到 O(n)
给数组，找和为 target 的两数下标；变体：和为 k 的连续子数组个数。
**要点**
- 核心套路：边遍历边把「已见过的值/前缀和」塞进哈希，查「target − 当前」是否出现过。
- 两数之和：`seen[x] = i`，查 `target - nums[i]`，一次扫描 O(n)/O(n)。
- 和为 k 子数组：维护前缀和 `pre`，哈希计数 `cnt[pre]`，答案累加 `cnt[pre - k]`；注意初始化 `cnt[0]=1`。
- 易错：重复值、负数（前缀和法照样成立，滑窗法不行）；先口头报暴力，再讲优化。

### [ds-02] 双指针：有序数组 / 链表的对撞与快慢指针
**要点**
- 对撞指针（有序数组求两数和、盛水容器、三数和）：左右往中间逼，按大小移动一侧，O(n)。
- 快慢指针：判环（Floyd）、找环入口、找链表中点、删倒数第 k 个。
- 三数和：先排序 O(n log n)，固定一个数 + 内层对撞；记得跳过重复元素去重。
- 滑动窗口是双指针特例：右扩满足条件、左缩维持约束（最长无重复子串、最小覆盖子串）。

### [ds-03] BFS / DFS：图与矩阵的遍历骨架
**要点**
- BFS 用队列，逐层扩展，适合**最短路（无权图）**、层序；DFS 用栈/递归，适合连通块、回溯、拓扑。
- 矩阵岛屿类：遍历每格，遇到未访问的陆地起一次 DFS/BFS 淹没，计数即连通块数。
- 必带 `visited`（或原地改值）防重复入队/栈溢出；记录 `(节点, 步数)` 或按层 size 出队算距离。
- 拓扑排序 = BFS（Kahn，入度为 0 入队）或 DFS 逆后序；可顺带检测有向图环。

### [ds-04] 动态规划：状态定义 + 转移 + 边界
经典：爬楼梯、打家劫舍、最长公共子序列、0/1 背包、编辑距离。
**要点**
- 三步：定义 `dp[i]` 含义 → 写转移方程 → 定边界与遍历顺序；先想清楚「状态」是什么。
- 一维：打家劫舍 `dp[i]=max(dp[i-1], dp[i-2]+a[i])`，常可滚动到 O(1) 空间。
- 二维：LCS `dp[i][j]=dp[i-1][j-1]+1`（相等）/ `max(dp[i-1][j],dp[i][j-1])`；编辑距离三选一取 min。
- 背包：0/1 容量逆序遍历、完全背包正序；面试先写朴素 DP，再谈空间压缩与复杂度。

### [ds-05] 堆 / Top-K：用优先队列管理「最值」
**要点**
- 求前 K 大用**大小为 K 的小顶堆**（堆顶是当前第 K 大，新元素比堆顶大才入），O(n log k) 优于全排序 O(n log n)。
- 第 K 大也可用 Quickselect 平均 O(n)；面试讲清两种取舍（堆适合流式/海量）。
- 合并 K 个有序链表：堆里放各链表头，弹最小再推下一个，O(N log k)。
- 数据流中位数：大顶堆存小一半 + 小顶堆存大一半，保持 size 差 ≤ 1。

### [ds-06] 复杂度分析：时间/空间与摊还
**要点**
- 报复杂度先看主循环嵌套与每步代价；哈希查/插平均 O(1)、最坏 O(n)（碰撞）。
- 递归用「递归树 / 主定理」：二分类 T(n)=T(n/2)+O(1)→O(log n)；归并 T(n)=2T(n/2)+O(n)→O(n log n)。
- 空间别忘**递归栈深度**（DFS 最坏 O(n)）和返回结果占用。
- 摊还：动态数组 push 均摊 O(1)；单调栈每元素进出各一次 → 整体 O(n)。

## ML 系统设计

### [ms-01] 设计一个信息流推荐 / 排序系统
场景：某社交产品 Helios Media 要给用户推内容流，DAU 千万级。
**要点**
- 先澄清：目标（停留时长/互动/留存？）、规模（item/user 量级、QPS、延迟预算）、冷启动、内容类型。
- 经典两阶段：**召回（recall）** 从亿级缩到千级（双塔/ANN、协同过滤、规则召回多路并集）→ **精排（ranking）** 用重模型打分（GBDT / DNN / 多目标）。
- 多目标：点击/时长/点赞用多任务或加权融合 `score = Σ wᵢ·pᵢ`，权重由业务和实验定；上层可加重排（多样性、去重、商业规则）。
- 特征：用户画像、item 内容/统计、上下文、交叉特征；强调离线/在线特征一致与新鲜度。
- 评估：离线 AUC/NDCG/Recall@K + 在线 A/B（核心指标 + 护栏如举报率）；上线后监控与回滚。

### [ms-02] 特征平台（Feature Store）要解决什么
**要点**
- 痛点：训练用离线批特征、线上服务要低延迟取同样特征，二者口径易不一致 → skew。
- 双存储：**离线**（数仓/湖，给训练与回填，吞吐优先）+ **在线**（KV 如 Redis，给推理，低延迟），同一份定义生成两边。
- 关键能力：特征定义/注册与复用、point-in-time correct join（防标签泄漏未来特征）、版本与血缘、TTL/新鲜度、监控。
- 收益：避免重复造特征、训练-服务口径统一、加速实验；面试落到「同一套 transform 生成线上线下」是答题锚点。

### [ms-03] 训练-服务偏斜（training-serving skew）怎么排查与防
**要点**
- 三类来源：① 特征工程代码两套（训练 pandas、线上 Java）口径漂；② 数据分布漂移（线上分布 ≠ 训练分布）；③ 时间穿越/标签泄漏（训练用了线上拿不到的未来特征）。
- 防：特征逻辑单一来源（feature store / 共享库）、记录并比对线上线下特征分布、point-in-time join、影子流量回放校验。
- 监控：线上打分分布、特征缺失率/默认值占比、预测值 vs 实际反馈（calibration），漂移告警。
- 答题落点：先定位是「特征不一致」还是「分布漂移」，前者治工程一致性，后者靠监控 + 重训/在线学习。

### [ms-04] 在线评估 vs 离线评估、A/B 实验
**要点**
- 离线：用历史数据算 AUC/NDCG/LogLoss/Recall@K，快、便宜，但有**离线-在线 gap**（无反馈回路、分布变化、位置偏差）。
- 在线 A/B：随机分流对比核心指标 + 护栏指标；先看 SRM（样本比例失衡）再读结果，预设样本量与时长防偷看。
- 反事实/离线策略评估（IPS、replay）可在上线前估线上效果，缓解 gap。
- 答题套路：离线选模 → 小流量在线灰度 → A/B 验证核心指标涨且护栏不破 → 全量；强调护栏与回滚阈值。

### [ms-05] 模型上线、监控与回滚
**要点**
- 上线方式：灰度/金丝雀（1%→10%→100%）、影子模式（只打分不生效，对比线上）、A/B 分桶。
- 监控分层：① 系统（QPS/延迟/错误率）② 数据（特征缺失、分布漂移）③ 模型（预测分布、calibration、核心业务指标）。
- 回滚：预设触发阈值（核心指标跌 X%、护栏破线、错误率飙升）→ 一键切回上一个稳定版本；模型与特征都要可版本化回滚。
- 强调可观测性 + 自动告警 + 明确 owner 和 runbook，别等用户投诉才发现。

### [ms-06] 召回 + 精排两阶段架构的取舍
**要点**
- 为什么分两阶段：直接对亿级 item 跑重模型不可行；召回粗筛（高召回、低延迟、便宜）→ 精排精算（高精度、可上重特征/重模型）。
- 召回多路：协同过滤、双塔向量 + ANN（HNSW/IVF）、热门/规则/新内容召回，结果取并集去重。
- 精排：特征丰富（交叉、序列、上下文）、模型重（DNN/GBDT/多任务），打分排序；可再加重排做多样性/打散/商业目标。
- 取舍：召回越多精排压力越大、延迟越高；漏斗各层的 Recall 与延迟预算要联合调，监控「召回是否限制了精排上限」。

## ML 基础

### [mf-01] 偏差-方差权衡（bias-variance tradeoff）
**要点**
- 泛化误差 ≈ 偏差² + 方差 + 不可约噪声。高偏差=欠拟合（模型太简单），高方差=过拟合（对训练集太敏感）。
- 加模型复杂度/特征 → 偏差↓方差↑；正则化/更多数据/简化模型 → 方差↓。
- 诊断：训练误差高 = 偏差问题（加复杂度/特征）；训练低、验证高且差距大 = 方差问题（正则、加数据、early stop）。
- 学习曲线（训练/验证误差随样本量）是判断该「加数据」还是「加复杂度」的实操工具。

### [mf-02] 过拟合与正则化（L1/L2、dropout、early stopping）
**要点**
- 过拟合信号：训练指标远好于验证；治理三方向：更多/增广数据、降模型复杂度、加正则。
- L2（岭）：惩罚权重平方，权重整体变小更平滑；L1（Lasso）：惩罚绝对值，产生**稀疏**解可做特征选择；Elastic Net 折中。
- 神经网络：dropout（训练随机丢神经元）、weight decay、early stopping（验证误差回升即停）、BatchNorm/数据增广。
- 树模型：限深、min_samples_leaf、subsample/colsample、学习率小 + 早停（GBDT）。

### [mf-03] 分类评估指标：precision/recall/F1/ROC-AUC/PR-AUC
**要点**
- Precision=TP/(TP+FP)「报出来的有多准」；Recall=TP/(TP+FN)「该抓的抓到多少」；F1=两者调和平均。
- 阈值权衡：调阈值在 P 与 R 间移动；按业务选——欺诈/疾病重 Recall，垃圾拦截重 Precision。
- ROC-AUC：TPR vs FPR 曲线下面积，阈值无关、衡量排序能力；**类别极不平衡时 PR-AUC 更敏感**、更能反映正类表现。
- 别只看 accuracy：99% 负样本时全猜负就 99% accuracy 却毫无用；多分类用 macro/micro 平均。

### [mf-04] 回归评估指标：MSE/RMSE/MAE/R²/MAPE
**要点**
- MSE/RMSE：平方放大大误差、对离群点敏感；RMSE 与目标同量纲好解释。MAE：绝对误差、对离群点更稳健。
- 选择：在意大误差/可导优化 → MSE；有离群点、要稳健 → MAE（或 Huber 折中）。
- R²：解释方差占比，可为负（比常数预测还差）；MAPE 看相对误差但目标接近 0 时爆炸、且对低估高估不对称。
- 报指标时说清量纲与对离群点的态度，并结合业务可接受误差。

### [mf-05] 类别不平衡怎么处理
**要点**
- 数据层：过采样少数类（SMOTE 合成）、欠采样多数类、或两者结合；注意只在**训练集**做、别污染验证/测试。
- 算法层：类权重 `class_weight`/加权损失、focal loss（降低易分样本权重）。
- 评估层：别用 accuracy，用 PR-AUC、F1、recall@某 precision；阈值按业务调而非默认 0.5。
- 先问「不平衡是否真有害」——有些任务模型本就能学好；优先调评估与阈值，再考虑重采样。

### [mf-06] 树模型 vs 神经网络：怎么选
**要点**
- 表格/结构化数据中小规模：GBDT（XGBoost/LightGBM）通常又快又准、对特征缩放不敏感、可解释（特征重要性/SHAP），是强默认。
- 非结构化（图像/文本/语音/序列）、超大数据：深度网络（CNN/Transformer）能端到端学表征、可迁移学习。
- 取舍维度：数据量与类型、特征工程成本、可解释性、延迟/算力、是否需在线学习与迁移。
- 集成：随机森林（bagging 降方差）vs GBDT（boosting 降偏差，逐棵拟合残差）；面试能讲清两者机制差异加分。

### [mf-07] Embedding 与表征学习
**要点**
- Embedding = 把高维稀疏 ID（词/用户/item）映射到低维稠密向量，捕捉语义/行为相似度，相近的东西向量也近。
- 来源：监督任务端到端学（推荐双塔）、自监督（word2vec、对比学习）、预训练大模型抽取。
- 用法：相似度检索（余弦/点积 + ANN）、做下游特征、冷启动可用内容 embedding 兜底。
- 注意维度选择、归一化、OOV/冷启动处理、向量随分布漂移需定期重训。

### [mf-08] 损失函数怎么选 + 特征工程要点
**要点**
- 损失：回归用 MSE/MAE/Huber；二分类用交叉熵（log loss）；多分类用 softmax 交叉熵；排序用 pairwise/listwise（BPR、LambdaRank）。
- 交叉熵优于平方误差做分类：梯度更好、与概率/极大似然一致、不易梯度消失。
- 特征工程：缺失值（填充 + 缺失标记）、类别编码（one-hot/target/embedding）、数值（标准化/分桶/对数）、交叉与时间特征。
- 防泄漏：只用预测时点可得的信息、按时间切分、归一化参数只在训练集 fit 再 transform 到验证/测试。

## 行为面

### [bh-01] STAR 框架：把经历讲成 2 分钟的故事
**要点**
- Situation/Task/Action/Result：背景一句带过，**重点在 Action（你做了什么、为什么这样选）和量化 Result**。
- 用「我」而非「我们」讲清个人贡献；提冲突/取舍/失败更可信，别只报喜。
- 结果量化：指标涨跌、延迟下降、成本节省、覆盖面；没硬数据就给相对量级或业务影响。
- 准备 5–6 个可复用故事（上线、救火、跨团队、冲突、失败、影响力），按问题灵活映射。

### [bh-02] 跨团队 / 跨职能协作（与产品、数据、平台、对端工程）
**要点**
- 讲清楚：利益相关方是谁、目标/口径不一致在哪、你如何对齐（数据/文档/共识机制）。
- 强调主动沟通、用数据/原型说话、建立单一信息源，把模糊问题推出方向。
- 给冲突的具体处理：先理解对方约束，再找共同目标和可量化的取舍，而不是各执一词。
- 结果落到「协作机制改善 + 业务/项目推进」，并反思下次怎么更早对齐。

### [bh-03] 模型上线事故复盘（ML incident postmortem）
讲一次你负责的模型/系统出问题（指标骤降、线上 bug、数据漂移）如何处置与复盘。
**要点**
- 时间线讲清：怎么发现（监控/告警还是用户反馈？）、影响范围、止血动作（回滚/降级/切规则）。
- 根因：常见为训练-服务 skew、特征上游数据变更、标签泄漏、分布漂移、发布配置错；讲清你怎么定位。
- 复盘产出：blameless、根因 + 行动项（加监控/加测试/改流程），并落实防复发。
- 体现 ownership：主动承担、推动系统性改进，而非甩锅；讲清你从中学到什么。

### [bh-04] Ownership 与处理模糊 / 优先级冲突
**要点**
- Ownership：超出本职范围主动补位、对结果负责到底、主动暴露风险而非藏问题。
- 模糊任务：先澄清目标与成功标准、拆解可交付的里程碑、快速做小可验证 spike 减少不确定性。
- 优先级冲突：用影响/成本/紧急度排序，与相关方对齐取舍，明确「先不做什么」并说明理由。
- 结果导向：讲清你的判断如何带来业务价值，以及事后如何回看决策、迭代改进。
