# Mock 面试题库 + 自评表（W3）— Data Engineer

> Week 3 实战化用：抽一组当全真 mock 跑，录音，按下方自评表打分。题与 [question-bank.md](question-bank.md) 同源、可混抽。

## 如何跑一场 45 分钟 mock

- **0–5 分钟**：面试官读题，你**出声复述 + 问澄清**（数据规模、延迟要求、口径、边界、上下游）。不澄清直接动手是最常见扣分项。
- **5–35 分钟**：边写边讲。SQL/Coding 题先讲思路再写；设计题先画整体数据流再逐组件下钻。
- **35–43 分钟**：自查——边界、复杂度、失败/重试、数据质量；主动报你知道的坑与 trade-off。
- **43–45 分钟**：反问面试官（团队的数据栈 / 最大挑战），收尾。
- 用手机/录屏录下来，按自评表逐项打分，写"最大 1 个坑 + 下次改 1 件事"。

## A. SQL & 建模（技术 + 建模轮）

- **A1**：`events(user_id, event_type, ts)`，求每个用户**连续活跃天数**的最长一段（经典 gaps & islands）。提示：`ROW_NUMBER` 减日期得分组键。
- **A2**：给订单 + 退款两张表，算每个商品的**净 GMV**与**退款率**，并标出退款率 > 全局均值的商品。考条件聚合 + 窗口对比。
- **A3**（建模口述）：为一个内容平台设计分析数仓——事实表/维度表怎么切？"作者所属机构"会变（SCD），用 Type 几？给一致性维度的例子。
- **A4**：一张事件表里有重复（上游重发），写出按业务键保留最新一条的去重，并说明在管道里怎么从根上 dedup。

## B. Coding（Python / Spark）

- **B1**（Python）：一个放不进内存的 CSV，求某列的 Top-20 高频值，讲流式 + 外部分桶 + 堆，给复杂度。
- **B2**（Python）：合并两份用户表（主键重叠、字段冲突），讲冲突解决规则与超内存时的分块/Spark 退路。
- **B3**（Spark）：一个 `groupBy(user_id).agg(...)` 作业个别 task 极慢——定位倾斜并给至少两种解法（加盐两阶段聚合 / AQE / reduceByKey）。
- **B4**（Spark 概念）：画出一段含 `filter → join → groupBy` 的 DAG，标出 stage 边界与哪步触发 shuffle，并讲两个减少 shuffle 数据量的优化。

## C. 管道 / 系统设计（设计轮）

- **C1**：设计把业务 MySQL **近实时同步到数仓**的管道（CDC）——snapshot + binlog、乱序、update/delete、幂等 upsert、schema 演进。
- **C2**：某核心日表**每天延迟**导致下游拿隔夜数据——你怎么诊断瓶颈、改造（分区/增量/调度/格式）并加 SLA 监控。
- **C3**：同一指标，给出**批方案与流方案**各一套，讲清延迟/成本/回填/容错的 trade-off 与你的推荐及理由。
- **C4**：设计一套**数据质量护栏**：哪些检查、卡在管道哪一步、失败如何阻断下游、怎么做新鲜度/血缘/数据契约。

## D. Behavioral（行为面）

- **D1**：讲一个你 owned 的数据管道/平台改进（量化影响）。→ [behavioral/README](behavioral/README.md) Story 1
- **D2**：讲一次数据事故/质量问题的复盘（止血 → 根因 → 系统性预防）。→ Story 2
- **D3**：讲一次与上游/下游团队就口径或质量的分歧怎么推进。→ Story 3
- **D4**：Tell me about yourself（DE 版 60–90s 电梯陈述）。
