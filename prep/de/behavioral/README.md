# 行为面（Behavioral）— Data Engineer

> 故事正文用 **英文**（面试对外）。DE 重点：**项目 ownership、可靠性思维、跨团队协作（上游业务库团队 / 下游分析与产品）、数据事故复盘、在模糊需求中带出方向**。资深岗更重系统性影响（建机制/立规范，而非一次性救火）。
> 这是一个**空模板**：用下面的结构和提示，让 Claude 把你自己的经历填成 STAR 故事。**只用脱敏口径**——不写真实公司名/人名，量化影响用相对值或虚构占位。

## STAR 是什么（30 秒）

- **S**ituation：背景与痛点（一句话）。
- **T**ask：你的职责——你具体要解决什么。
- **A**ction：你做了什么，突出**技术判断与取舍**（为什么这么设计、否决了什么），而非流水账。
- **R**esult：量化影响（延迟降幅、成本降幅、SLA 达成、影响的下游数）。

## DE 行为面四类必备故事

| # | 故事主题 | 对应考点 | 状态 |
|---|---|---|---|
| 1 | 我 owned 的数据管道/平台改进 | Ownership / Impact / 可靠性 | ⬜ 待写 |
| 2 | 一次数据事故 / 质量问题的复盘 | 事故处理 / 系统性预防 | ⬜ 待写 |
| 3 | 与上游或下游团队的分歧与推进 | 跨团队协作 / 影响力 | ⬜ 待写 |
| 4 | 模糊需求 / 技术债权衡下做决策 | 判断力 / 资深信号 | ⬜ 待写 |

## 故事草稿（英文）

### Story 1 — <主题，如"把核心管道延迟从隔夜降到小时级">（Ownership / Impact）

- **Situation:** <背景占位——如核心日表每天延迟、下游频繁拿到隔夜数据>
- **Task:** <你的职责占位——你要把它改造成按时、可靠>
- **Action:** <行动占位——改增量、调分区、优化 shuffle、加 SLA 监控；讲清你否决了什么方案、为什么>
- **Result:** <结果占位——延迟从 X 降到 Y、SLA 达成率、影响 N 个下游（脱敏/相对值）>
- **考点映射:** Impact / 可靠性 / 规模

### Story 2 — <主题，如"一次线上数据错误的复盘">（事故处理 / 预防）

- **Situation:** <背景占位——线上指标异常/管道挂了>
- **Task:** <你的职责占位——止血 + 找根因 + 防再犯>
- **Action:** <行动占位——怎么发现（监控 vs 投诉）、止血/回填、5 Why 定位根因、补护栏（断言/数据契约/幂等改造/runbook）>
- **Result:** <结果占位——MTTR、同类事故下降、护栏拦下次数>
- **考点映射:** Failure / 系统性预防 / blameless

### Story 3 — <主题，如"推动上游建立数据契约">（跨团队 / 影响力）

- **Situation:** <背景占位——上游频繁改 schema 打挂你 / 下游对口径有分歧>
- **Task:** <你的职责占位——推动一个不再反复出问题的机制>
- **Action:** <行动占位——用数据/影响说话量化 breakage，推动数据契约/评审流程/统一口径，给对方也省事的方案>
- **Result:** <结果占位——breakage 下降、流程落地、成为团队标准>
- **考点映射:** Influence / Cross-functional / Conflict

### Story 4 — <主题，如"在交付期限与技术债之间取舍">（判断力）

- **Situation:** <背景占位——既要赶产出又面临架构债>
- **Task:** <你的职责占位>
- **Action:** <行动占位——怎么权衡短期交付与长期可维护、怎么沟通、分阶段落地>
- **Result:** <结果占位（量化）>
- **考点映射:** Judgment / Trade-off / 资深信号

## 答题提醒（DE 专属）

- 多数 DE 故事可落到**可靠性、规模、成本、对下游的同理心**这几个信号上——讲完点出来。
- 量化 > 形容词；但**脱敏**：用相对值（"延迟降 80%"）或虚构占位，别写真实绝对数与公司/人名。
- 事故题用 **blameless** 口吻（对事不对人），重点放"系统性预防"而非"我多努力救火"。
- 资深岗：体现你**建了机制 / 立了规范 / 被复用**，而非单点英雄主义。
